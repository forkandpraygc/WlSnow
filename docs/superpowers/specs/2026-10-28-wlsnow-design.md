# WlSnow — нативный Wayland-аналог XSnow (дизайн)

Дата: 2026-10-28

## Intent / Зачем

XSnow рисовал падающие снежинки и сугробы поверх рабочего стола X11. На Wayland он
не работает: нет корневого окна, и произвольный клиент не может рисовать поверх
всего. WlSnow — нативный Wayland-эквивалент: падающий снег, отрисованный как
слой (layer-shell), для wlroots-композиторов и KDE Plasma.

## Цели

- MVP: анимированные падающие снежинки поверх рабочего стола через `wlr-layer-shell`.
- Работает на wlroots (Sway, Hyprland, Wayfire, river); KDE KWin — best-effort
  (верифицируем позже).
- Управляющий интерфейс через Unix-сокет для запуска/паузы/настройки.

## Не-цели

- Снег поверх окон (без кооперации с композитором невозможно).
- Поддержка GNOME (нет layer-shell) — отложена/не планируется.
- GPU-отрисовка (CPU в `wl_shm` достаточно для снежинок).
- Пасхалки (лыжник, рождественский режим).
- Дробное масштабирование (только целочисленный scale).

## Анти-цели

- Не должно требовать XWayland или X11.
- Не должно быть «полноэкранным окном», перехватывающим фокус/ввод — используем
  layer-shell (слой bottom, позади окон) с пропуском указателя и клавиатуры.

## Ограничения

- Wayland: глобального рисования нет; механизм — `wlr-layer-shell` (только wlroots + KDE).
- Приложение декоративно: не должно перехватывать ввод.
- Язык: Rust.

## Approaches / рассмотренные варианты

### Язык
- **Rust (выбран)** вместо C или C++/Qt. Причины: безопасность памяти в долгоживущем
  графическом приложении, зрелый wayland-rs-стек, cargo для сборки/зависимостей.
- C — ближе к libwayland, но медленнее расширять; C++/Qt — оправдан только под KDE-first.

## Принятые решения

- Стек: Rust, `wayland-client` + `wayland-protocols` + `smithay-client-toolkit`
  (layer-shell).
- Отрисовка: CPU-снежинки в `wl_shm`-буфер, по одной поверхности на каждый output,
  на слое bottom (поверх обоев, позади окон).
- Цикл кадров: перерисовка по frame callback, анимация позиций снежинок.
- Сугробы: снег копится у нижнего края экрана и при достижении порога обваливается.
- Scale: целочисленный (`set_buffer_scale`, буфер ×scale); дробный — позже.
- Управляющий интерфейс: минимальный версионированный протокол через Unix-сокет
  (старт/стоп/пауза, чтение/запись конфига: количество/скорость/размер снежинок).

## Что остаётся исполнителю

- Конкретные крейты и разбиение на модули.
- Модель анимации снежинок (ветер, дрейф, распределение скоростей).
- Формат CLI/конфиг-файла.
- Путь сокета и формат сообщений протокола (например, line-delimited JSON, версионированный).
