# WlSnow — нативный Wayland-аналог XSnow (дизайн)

Дата: 2026-10-28

## Intent / Зачем

XSnow рисовал падающие снежинки и сугробы поверх рабочего стола X11. На Wayland он
не работает: нет корневого окна, и произвольный клиент не может рисовать поверх
всего. WlSnow — нативный Wayland-эквивалент: падающий снег, отрисованный как
слой (layer-shell), для wlroots-композиторов и KDE Plasma. Параллельно закладывается
граница плагинов, чтобы позже добавлять дополнения под конкретные DE.

## Цели

- MVP: анимированные падающие снежинки поверх рабочего стола через `wlr-layer-shell`.
- Работает на wlroots (Sway, Hyprland, Wayfire, river); KDE KWin — best-effort
  (верифицируем позже/в KDE-плагине).
- Заложить основу системы плагинов (внешние процессы + управляющий сокет).

## Не-цели (MVP)

- Накопление сугробов / снег поверх окон (без кооперации с композитором невозможно).
- Поддержка GNOME (нет layer-shell) — отложена/не планируется.
- GPU-отрисовка (CPU в `wl_shm` достаточно для снежинок).
- Любые реальные DE-плагины — только граница/протокол.
- Пасхалки (лыжник, рождественский режим).
- Поддержка нескольких мониторов (в MVP — один output).
- Дробное масштабирование (в MVP — только целочисленный scale).

## Анти-цели

- Не должно требовать XWayland или X11.
- Не должно быть «полноэкранным окном», перехватывающим фокус/ввод — используем
  layer-shell (слой background, позади окон) с пропуском указателя и клавиатуры.

## Ограничения

- Wayland: глобального рисования нет; механизм — `wlr-layer-shell` (только wlroots + KDE).
- Приложение декоративно: не должно перехватывать ввод.
- Язык: Rust.

## Approaches / рассмотренные варианты

### Язык
- **Rust (выбран)** вместо C или C++/Qt. Причины: безопасность памяти в долгоживущем
  графическом приложении, зрелый wayland-rs-стек, cargo для сборки/зависимостей.
- C — ближе к libwayland, но медленнее расширять; C++/Qt — оправдан только под KDE-first.

### Граница плагинов
- **A. Внутрипроцессные C-ABI (`libloading`)** — отклонено: неудобно для DE-плагинов на
  родном языке DE (JS/GJS, C++/QML), падение плагина роняет всё приложение.
- **B. Внешние процессы + управляющий сокет (выбрано)** — языконезависимо, изолировано,
  DE-плагины живут в своём окружении. Внутрипроцессные точки расширения можно добавить
  позже при конкретной нужде (кастомная отрисовка).

## Принятые решения

- Стек: Rust, `wayland-client` + `wayland-protocols` + `smithay-client-toolkit`
  (layer-shell).
- Отрисовка: CPU-снежинки в `wl_shm`-буфер (растровый блит; конкретный крейт — на
  усмотрение исполнителя), одна поверхность на слое background (позади окон).
- Цикл кадров: перерисовка по frame callback (или таймеру), анимация позиций снежинок.
- Один output в MVP (мульти-монитор — позже).
- Scale: целочисленный (`set_buffer_scale`, буфер ×scale); дробный — позже.
- Основа плагинов в MVP: минимальный версионированный управляющий интерфейс через
  Unix-сокет (старт/стоп/пауза, чтение/запись конфига: количество/скорость/размер
  снежинок). Протокол версионирован и языконезависим. DE-плагинов в MVP нет.

## Что остаётся исполнителю

- Конкретные крейты и разбиение на модули.
- Модель анимации снежинок (ветер, дрейф, распределение скоростей).
- Формат CLI/конфиг-файла.
- Путь сокета и формат сообщений протокола (например, line-delimited JSON, версионированный).
